# BewpakornShop — ย้ายจาก Apps Script สู่ Supabase

สถานะ: เฟส 1-4 เสร็จแล้ว · **เฟส 5** (ลากวางจัดลำดับสินค้าและ Shop ID) ← แพ็กเกจนี้

## เฟส 5: ลากวางจัดลำดับสินค้าและ Shop ID

### 1) รัน migration
SQL Editor → วาง `supabase/migrations/006_shopid_order.sql` → Run (ต้องรัน 004 มาก่อน)
ไฟล์นี้เพิ่มลำดับ Shop ID แยกตามแมพ (ตั้งค่าเริ่มต้นตามลำดับที่เห็นอยู่ตอนนี้) และฟังก์ชัน `reorder_shop_ids` สินค้าไม่ต้องมี migration เพิ่ม

### 2) อัปเดตหน้าเว็บ
แตก zip ทับโฟลเดอร์เดิม → `cd web` → `npm run dev` (ไม่มีแพ็กเกจใหม่ แต่ถ้ายังไม่เคย `npm install` หลังเฟส 4 ให้ทำก่อน)

### 3) วิธีใช้
- **สินค้า**: เลือกแมพ → กด "↕️ จัดเรียงสินค้า" → ลากแถวไปวาง (บันทึกอัตโนมัติ) · ปุ่ม ⤒ ⤓ ย้ายไปบนสุด/ล่างสุด (สะดวกเมื่อรายการยาว) · มือถือ: กดค้างที่แถวแล้วลาก · คีย์บอร์ด: โฟกัสที่ ⠿ กด Space แล้วใช้ลูกศร Space อีกครั้งเพื่อวาง · กด "✅ เสร็จสิ้นการจัดเรียง" เพื่อออก
- **ไอดีร้าน**: เลือกแมพ → กด "↕️ จัดเรียง" → ใช้งานเหมือนกัน
- โหมดจัดเรียงใช้ได้ต่อเมื่อเลือกแมพเฉพาะ (ไม่ใช่ "ทั้งหมด") เพราะลำดับ 1..n ใช้ภายในแต่ละแมพ
- โหมดจัดเรียงของสินค้าแสดงสินค้าทั้งหมดของแมพ รวมที่ปิดอยู่ ไม่กรอง/ไม่ค้นหา เพื่อให้ลำดับ 1..n ครบถ้วน

### พฤติกรรมที่เปลี่ยน
- ช่องพิมพ์เลขลำดับในโหมดจัดเรียงสินค้าถูกแทนที่ด้วยการลากวาง (ฟอร์มแก้ไขสินค้ายังมีช่อง "ลำดับการแสดง" ให้พิมพ์เลขได้)
- มุมมองรวมทุกแมพ: การเรียง "ตามลำดับ" และ "แมพ" ของสินค้า รวมถึงรายการ Shop ID เรียงตามลำดับแมพที่คุณจัดไว้ก่อน แล้วตามลำดับภายในแมพ (ไม่มีแมพอยู่ท้ายสุด)
- Shop ID ใหม่ หรือที่ย้ายแมพ จะไปต่อท้ายของแมพนั้นอัตโนมัติ
- การจัดลำดับสินค้าไม่เปลี่ยนเวลา "อัปเดตล่าสุด"

## เฟส 4: ลากวางจัดลำดับแมพ · ตารางกะเป็นลิงก์ · เลิกระบบตารางงาน

### 1) รัน migration
SQL Editor → New query → วางแล้ว Run ทีละไฟล์:

1. **`004_maps_order.sql` (จำเป็น)** เพิ่มลำดับแมพ ตั้งค่าเริ่มต้นตามลำดับที่เห็นอยู่ตอนนี้ แมพใหม่ไปต่อท้ายอัตโนมัติ และเพิ่มฟังก์ชัน `reorder_maps` (ต้องมีสิทธิ์แก้ไขแมพ)
2. **`005_drop_schedule.sql` (ไม่บังคับ รันเมื่อแน่ใจ)** ⚠️ ลบตาราง `schedule`, `holiday_votes`, `holiday_locks`, `attendance_logs` พร้อมฟังก์ชันและสิทธิ์ที่เกี่ยวข้องถาวร ข้อมูลต้นฉบับยังอยู่ใน Google Sheet เดิมและไฟล์ xlsx ของคุณ (เก็บ xlsx ไว้เป็น backup) ระบบใช้งานปกติแม้ยังไม่รันไฟล์นี้

### 2) อัปเดตหน้าเว็บ (มีแพ็กเกจใหม่ ต้อง npm install)
แตก zip ทับโฟลเดอร์เดิม แล้ว
```
cd web
npm install
npm run dev
```
ไม่ต้องแก้ `.env` (ถ้าอยากเปลี่ยนลิงก์ตารางกะ ตั้ง `VITE_SCHEDULE_URL` ใน `web/.env`)

### 3) วิธีใช้
- **จัดลำดับแมพ**: เมนูแมพ → ลากการ์ดไปวาง บันทึกอัตโนมัติ · มือถือ: กดค้างที่การ์ดสักครู่แล้วลาก · คีย์บอร์ด: โฟกัสที่ ⠿ กด Space แล้วใช้ลูกศร กด Space เพื่อวาง ลำดับนี้ใช้กับตัวเลือกแมพทุกหน้า (สินค้า, Shop ID, นับสต็อก, ฟอร์ม)
- **ตารางกะ**: เมนู "ตารางกะ" มีปุ่มเปิดเว็บตารางกะในแท็บใหม่ และปุ่ม "แสดงในหน้านี้" (ฝังในหน้าเว็บเรา ถ้าเว็บนั้นอนุญาต) ทุกคนที่ล็อกอินเห็นเมนูนี้
- เมนูโหวตวันหยุดและเช็กอินถูกเอาออกแล้ว

### การติดตั้งใหม่ทั้งชุด (กรณีย้ายไปโปรเจค Supabase ใหม่)
รันตามลำดับ: `001_schema.sql` → ข้อมูล (`npm run import:sql` แล้ววางไฟล์ใน `out/`) → `002` → `003` → `004` → `006` (→ `005` ถ้าต้องการ)
สคริปต์ `import` ข้ามตารางที่เลิกใช้แล้วให้อัตโนมัติ

## เฟส 3: แมพ / สินค้า / Shop ID / นับสต็อก

### 1) รัน migration 003
Supabase Dashboard → SQL Editor → New query → วาง `supabase/migrations/003_products_logic.sql` ทั้งหมด → Run

ไฟล์นี้ย้ายตรรกะจาก Code.gs มาไว้ที่ฐานข้อมูล:
- **สต็อกเซ็ต (Bundle) คำนวณอัตโนมัติ** ทุกครั้งที่สต็อกสินค้าย่อยหรือ Ghost เปลี่ยน (แทน `recalcBundleStocks_`)
- **Ghost item เป็นแหล่งข้อมูลเดียว** สต็อก Ghost อยู่ในตาราง `ghost_items` ที่เดียว (ของเดิมเก็บซ้ำทั้งในชีต GhostItems และ JSON ของสินค้า แล้วต้อง sync สองทาง)
- ฟังก์ชัน `save_product`, `save_stock_count`, `bulk_update_sort` (ตรวจสิทธิ์ที่ฐานข้อมูล)

### 2) อัปเดตหน้าเว็บ
แตก zip ทับโฟลเดอร์เดิม แล้ว `cd web` → `npm install` (ถ้าไม่มีแพ็กเกจใหม่จะเร็ว) → `npm run dev`
ไม่ต้องแก้ `.env`

### 3) ลองใช้
ล็อกอินด้วยบัญชี admin (`bew`) แล้วลองตามนี้:
1. **แมพ**: เพิ่ม/แก้/ลบแมพ
2. **Shop ID**: เพิ่มทีละตัวและหลายตัว (วางหลายบรรทัด) กดตา 👁 ดูรหัสผ่าน
3. **สินค้า**: กรองตามแมพ/สถานะ/ประเภท, ค้นหา, เรียงลำดับ, ดูรายละเอียด, เพิ่ม/แก้ไข, ลองสร้างเซ็ตที่มี Ghost, โหมด "จัดเรียงสินค้า", ส่งออก CSV
4. **นับสต็อก**: ลองปรับตัวเลข แล้วบันทึกทีละรายการและบันทึกทั้งหมด จากนั้นดูว่าสต็อกของเซ็ตที่เกี่ยวข้องเปลี่ยนตามเอง
5. ล็อกอินด้วยบัญชี staff ตรวจว่า **ไม่เห็นปุ่มแก้ไข/ลบ** และไม่มีเมนูนับสต็อก

### ข้อแตกต่างจากระบบเดิม (ตั้งใจ)
- สินค้าแบบเซ็ตในหน้านับสต็อก **แก้ตรงๆ ไม่ได้** (แสดงค่าที่คำนวณ ต้องแก้ที่ส่วนประกอบ) เพราะระบบเดิมเขียนทับแล้วถูกคำนวณกลับอยู่ดี
- ลำดับสินค้าใช้ตัวเลขอย่างเดียว (ตัวเลือก first/last ในฟอร์มเดิมไม่ได้ถูกใช้กับข้อมูลจริง)
- บันทึกลำดับสินค้า **ไม่เปลี่ยนเวลา "อัปเดตล่าสุด"** เหมือนเดิม
- ลบแมพ/Shop ID แล้วสินค้าไม่ถูกลบ แต่กลายเป็นไม่ระบุแมพ/ไอดี (ระบบเดิมทิ้งค่าค้างไว้)
- เพิ่ม Shop ID ที่ซ้ำจะถูกข้ามและแจ้งจำนวน
- ฟอร์มสินค้ารองรับการเติมข้อมูลอัตโนมัติเมื่อพิมพ์ชื่อตรงกับสินค้าเดิมในแมพเดียวกัน
- รายการสินค้าแสดงทีละ 100 แล้วกด "แสดงเพิ่ม"

### ทดสอบตรรกะ
`cd web && npm test` (ทดสอบสูตรสต็อกเซ็ตและตัวกรอง/เรียงลำดับ)

## เฟส 2: ขั้นตอน

### 1) รัน migration 002 (Auth + RLS)
Supabase Dashboard → SQL Editor → New query → วางไฟล์ `supabase/migrations/002_auth_rls.sql` ทั้งหมด → Run
(ถ้าเพิ่งทำเฟส 1 เสร็จ ตารางต้องมีข้อมูลอยู่แล้ว)

### 2) สร้างผู้ใช้ Auth จาก username + PIN เดิม
```
npm install
cp .env.example .env      # กรอก SUPABASE_URL และ SUPABASE_SECRET_KEY (sb_secret_...)
# วางไฟล์ xlsx ที่ data/stock.xlsx (ไฟล์เดียวกับที่ใช้ในเฟส 1)
npm run auth:users
```
ควรเห็น `✓` ครบ 7 คน และ `ผูกแล้ว 7/7 คน ✅` สคริปต์รันซ้ำได้ และย้ายรูปโปรไฟล์ base64 ไป Storage ให้ด้วย

> ถ้า createUser ฟ้อง error เรื่องอีเมล/โดเมน ให้เปลี่ยน `AUTH_EMAIL_DOMAIN` (ใน `.env` และ `VITE_AUTH_EMAIL_DOMAIN` ใน `web/.env`) เป็นโดเมนที่คุณเป็นเจ้าของ แล้วรันใหม่

### 3) รันหน้าเว็บบนเครื่อง
```
cd web
npm install
cp .env.example .env      # กรอก VITE_SUPABASE_URL และ VITE_SUPABASE_PUBLISHABLE_KEY (sb_publishable_...)
npm run dev
```
เปิด http://localhost:5173 แล้วล็อกอินด้วย username + PIN เดิม

### 4) deploy (เมื่อพร้อม)
push ขึ้น GitHub แล้วเชื่อมกับ Cloudflare Pages หรือ Vercel
- Root directory: `web` · Build command: `npm run build` · Output: `dist`
- ตั้ง Environment variables สามตัวจาก `web/.env.example`
- ห้ามใส่ secret key ในหน้าเว็บหรือ Environment ของ Pages เด็ดขาด

## สิทธิ์ที่บังคับที่ฐานข้อมูล (ต่างจากระบบเดิมที่เช็กแค่ในหน้าเว็บ)
- `admin` ทำได้ทุกอย่าง · role อื่นดูจากตาราง `permissions` (view/add/edit/delete/approve)
- พนักงานทั่วไป (staff) เห็นเฉพาะสินค้า/ไอดีร้านตามสิทธิ์ แก้ไม่ได้
- โหวตวันหยุด: โหวตได้เฉพาะของตัวเอง สถานะเริ่ม pending เสมอ, สูงสุด 4 วัน, ห้ามวันที่ถูกล็อก, ห้ามวันที่มีกะแล้ว; แก้/ลบของตัวเองได้จนกว่าจะถูกอนุมัติ; อนุมัติได้เฉพาะผู้มีสิทธิ์ schedule/holidays approve หรือ admin
- เช็กอิน: บันทึกได้เฉพาะของตัวเอง เวลาใช้ของเซิร์ฟเวอร์ (admin ลงแทน/ย้อนเวลาได้)
- รหัสผ่านไอดีร้าน (`shop_ids.password`) อ่านได้เฉพาะผู้มีสิทธิ์ view ของ shopids

## การล็อกอิน
username → อีเมลสมมติ `username@<โดเมน>` และรหัสผ่านคือ `bwk-` + PIN (เพราะ Supabase บังคับรหัสผ่านอย่างน้อย 6 ตัว แต่ PIN เดิมบางอันสั้นกว่า) พนักงานยังกรอกแค่ username + PIN เหมือนเดิม
**แนะนำให้เปลี่ยนเป็น PIN ที่ยาวขึ้นหลังย้ายเสร็จ** PIN 4 หลักเดาง่าย
